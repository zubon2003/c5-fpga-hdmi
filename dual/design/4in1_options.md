# C5VRX 4台（4in1）にするためのハードウェア案

2026-10-06（スレッド1）。前提は [interface.md](interface.md)。

## 必要なもの

| 項目 | 4台分 |
|---|---|
| FPGA の入力ピン | 6bit × 4 = **24本**（クロックも取るなら +4 で 28本） |
| フレームバッファ | 必須。4台は互いに同期していないので、出力を1台に合わせる方式は使えない |
| メモリ帯域 | 書き込み 4台 × 640×240×2B×60 ≈ 74MB/s、読み出しも同程度 |
| 乗算器 | 時分割で 1台あたり約4個 + 出力側 8個 ≈ **24個** |
| HDMI 出力 | 720p |

画面の分け方: 4分割（各 640×360、縦 1.5 倍）、または4台ダイバーシティ（良い1台を全画面）。

## 案の比較

| 案 | 構成 | 使える入力ピン | メモリ | 乗算器 | 判断 |
|---|---|---|---|---|---|
| **A. Tang Nano 20K のキャリア基板（推奨）** | Nano 20K と XIAO 4台を1枚の基板に載せる | 34本（左右のピンヘッダ） | 64Mbit（8MB）SDRAM を内蔵 | 48個（18×18） | 24本が余裕で取れ、HDMI 端子と SDRAM が最初から付いている。基板1枚で済む |
| B. Tang Primer 25K のまま、C5VRX を 4bit に | 1台 4本 × 4 = 16本で Pmod 2つに収まる | 16本 | 32MB SDRAM（J3） | 28個 | 配線は今の案のまま。ただし C5VRX の 4bit モードは試験的で、階調が 16 段に落ちる。データも速く（80MHz）なり受信が難しくなる |
| C. Tang Mega 60K Dock | HDMI と DDR3 512MB 付き。2×20 ヘッダ2本（Pmod と共用） | 数十本 | 512MB DDR3 | 多数 | 性能は最も余裕があるが、ボードが高価で大きい。DDR3 の扱いも難しくなる |
| **E. Tang Console 60K（2026-10-06 追記）** | HDMI 端子付きの Console ボードに Mega 60K SOM。独立した 2×20 ヘッダ2本に XIAO 4台のドーターを挿す | ヘッダ2本で最大 76本（Pmod 2つは別に 16本） | SOM に 512MB DDR3 | 118個（18×18） | 資源は最も余裕がある（LUT 59,904、BSRAM 2.1Mbit）。ヘッダが Pmod と共用でないので HDMI・Pmod と干渉しない。DDR3 コントローラ（Gowin の IP）を使う必要がある |
| D. Primer 25K + 小さい FPGA をもう1つ | 追加の FPGA で2台分を受けて、まとめて 25K に送る | 増やせる | 25K の SDRAM | 28個 | FPGA が2つになり、両方のロジックと間の通信を作る必要がある。手間が最も大きい |

（Nano 20K のピン数は Sipeed のピン配置図から数えた。LCD コネクタ・LED・I2S・SD と共用のピンを含む。これらの部品を使わなければ I/O として使える。）

## 推奨: A. Tang Nano 20K キャリア基板

```
 ┌────────────── キャリア基板 ──────────────┐
 │  [XIAO-1]  [XIAO-2]   ┌──────────────┐    │
 │                        │ Tang Nano 20K │ ← HDMI 端子・USB-C は基板の端へ
 │  [XIAO-3]  [XIAO-4]   └──────────────┘    │
 │  5V 入力（USB-C 5V/2A）                    │
 └────────────────────────────────────────────┘
```

- Nano 20K は両側に 2.54mm ピンヘッダがあるので、キャリア基板にメスヘッダで挿す。
- XIAO 4台の D4〜D9 を Nano 20K の I/O 24本へ配線する。D0〜D3, D10 は未接続（C5VRX の IQ 取り込み用）。
- 電源はキャリア基板の 5V を Nano 20K の 5V ピンと各 XIAO の 5V ピンへ（XIAO はダイオード経由）。
  合計 0.8A 前後なので 5V/2A 以上の電源を使う。
- FPGA ロジックは 25K 向けと同じ考え方（160MHz オーバーサンプリング → デコード → SDRAM → 720p）。
  ただしチップが違う（GW2AR-18）ので、PLL や SDRAM コントローラは Nano 20K 用のものを使う。
- 気になる点:
  - 内蔵 SDRAM の帯域は足りる見込みだが、4分割では書き込みと読み出しを合わせて 150MB/s 程度になる。合成とテストで確認が要る。
  - LUT は 20,736 個で、デコーダ4つ分が入るかは要確認。足りなければ色の処理を2台分に絞る。
  - 5.8GHz のアンテナ4本が近づくので、基板の配置でアンテナ同士と HDMI ケーブルから離す。

## E. Tang Console 60K を使う場合

- Sipeed Wiki によると、Console は 2×20 ピンヘッダ2本（最大 2×38 本の I/O、DE10-Nano 互換に改造可能）、Pmod 2つ（800mil 間隔）、HDMI 出力を持つ。
  SOM（GW5AT-LV60）は LUT 59,904、BSRAM 2,124Kbit、乗算器 118個、DDR3 512MB。
- XIAO 4台分の 24本（クロックを取るなら 28本）は **ヘッダ1本（38本）に収まる**。もう1本のヘッダと Pmod は空いたまま。
  将来 8台にすることもピン数の上では可能。
- 4台をカラーでデコードしても乗算器は 118個中 30個程度、BSRAM も余裕があるので、出力を入力に同期させる低遅延のラインバッファ方式と、DDR3 のフレームバッファ方式の両方が選べる。
- 気になる点:
  - DDR3 は SDRAM よりコントローラが複雑。Gowin の DDR3 IP（Sipeed の TangMega-60K-example や nand2mario の tangcores に使用例あり）を使う。
  - 開発環境は Gowin IDE の教育版 V1.9.11.03 以降、または商用版 V1.9.10.03 以降が必要（Sipeed Wiki）。
  - 2×20 ヘッダの電源ピン（5V/3V3 がどのピンに出ているか）はまだ確認していない。Console の回路図で確認が要る。
  - 25K / Nano 20K よりボードが大きく、価格も高い。

### Nano 20K（案 A）との比べ方

| | Nano 20K キャリア | Console 60K + ドーター |
|---|---|---|
| 基板 | キャリア1枚（Nano 20K を載せる） | ドーター1枚（ヘッダに挿す） |
| 資源の余裕 | ぎりぎり（SDRAM 帯域・LUT を要確認） | 大きい |
| メモリ | 8MB SDRAM（簡単） | 512MB DDR3（IP が必要） |
| 大きさ・価格 | 小さく安い | 大きく高い |
| 向いている使い方 | 小型の受信機として仕上げる | まず確実に 4台を動かす、さらに増やす |

**手元に Console 60K がある、または買うつもりなら、4in1 は Console 60K を推奨**（資源不足の心配がない）。
小型化を優先するなら Nano 20K。

## 今の 2台構成との関係

- 2台構成（Primer 25K + Pmod）はそのまま進められる。FPGA のロジック（受信、デコード、SDRAM、720p）は Nano 20K にもほぼ移植できる。
- 4in1 を本命にするなら、最初から Nano 20K で作るほうが基板が1枚で済み、Pmod の干渉の心配もない。
