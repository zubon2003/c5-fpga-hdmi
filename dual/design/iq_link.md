# IQ 転送方式（C5VRX ×2 → Tang Primer 25K、FM 復調を FPGA で行う）

2026-10-12（スレッド「IQ転送」）。前の CVBS 転送方式は [interface.md](interface.md)（これは変更していない）。

## 0. 結論

- **IQ は Pmod の 8 本にちょうど収まる**。各 XIAO から 4bit I + 4bit Q = 8bit を 40MS/s で送る（1台 320Mbps）。クロック線は使わず、FPGA が 150MHz で取り込む（今の CVBS 受信と同じ方式）。
- **ゲインなどの受信状態は UART（2Mbaud）で送る**。Pmod に空きが無いので、**Dock の USB-A 端子の D+ / D− を FPGA の入力として使う**（D+ = XIAO-A、D− = XIAO-B）。
- **ファームは C5VRX-5（`v5/`）に約 100 行の変更**。IQ を XIAO の端のピンに移し、受信状態を送るタスクを足す。ビルド確認済み。
- **アダプタ rev A は線 3 本の改造で使える**（D0、D1、D10）。
- FPGA 側は `fpga_iq/`（新しいプロジェクト）。シミュレーションで NTSC / PAL、ダイバーシティ切替、2画面が動作。DSP は 8 個（28 個中）。

## 1. C5VRX の IQ の中身（ソースで確認）

C5VRX（2026-10-11 の main、`v5/main/rf.c`、`main/rf.c`）を読んだ結果:

| 項目 | 値 |
|---|---|
| 出どころ | ESP32-C5 の MODEM_DIAG バス（ADC の値を GPIO マトリクス経由でピンに出す） |
| レート | 40MS/s（C5VRX の PARLIO RX は内部 40MHz で読む） |
| 形式 | I と Q が各 4bit の 2 の補数。ADC 10bit のうち符号 bit9 と 3 bit を切り出したもの |
| ビット | bit 3:0 = Q、bit 7:4 = I（C5VRX-5 は ultrafine: ADC bit {9,6,5,4} 固定、±128 の窓） |
| クロック | ピンに出ていない。XIAO の 40MHz 水晶が元 |
| 駆動 | XIAO が出力（INPUT_OUTPUT）。FPGA は入力として並列に聞くだけ |

C5VRX-5 の調査メモ（`v5/docs/FINDINGS.md`）によると、4bit IQ そのものはほとんど情報を失っておらず、画質の損失は C5 内部の復調器（32 位相の格子、625kHz 刻み）で起きている。**FPGA で IQ から直接復調すれば、この損失を避けられる**。

## 2. ピン割り当て

ファームを変えて、IQ 8 本をすべて XIAO の端のピンに出す（C5VRX の既定は 3 本が裏面パッド）。

| IQ ビット | XIAO | GPIO | Pmod 位置 | XIAO-A → J4 | XIAO-B → J5 | rev A 基板 |
|---|---|---|---|---|---|---|
| Q0 | D4 | 23 | 1 | G11 | A11 | そのまま（33Ω） |
| Q1 | D5 | 24 | 2 | D11 | E11 | そのまま |
| Q2 | D6 | 11 | 3 | B11 | K11 | そのまま |
| Q3（符号） | D7 | 12 | 7 | G10 | A10 | そのまま |
| I0 | D8 | 8 | 8 | D10 | E10 | そのまま |
| I1 | D9 | 9 | 9 | B10 | L11 | そのまま |
| I2 | D0 | 1 | 4 | C11 | L5 | **改造: D0 → TP1** |
| I3（符号） | D1 | 0 | 10 | C10 | K5 | **改造: D1 → J1 の Pmod 10 番** |
| 受信状態 UART | D10 | 10 | − | USB-A D+（L6） | USB-A D−（K6） | **改造: D10 → USB-A** |

- 元の抵抗 DAC の出力は、アダプタがつないでいない D2、D3 と裏面の MTMS/MTDI/MTCK/MTDO に移す（どこにも出ない）。
- D0/D1（GPIO1/0）は ESP32-C5 の 32kHz 水晶用ピンで、起動時のストラップではない。FPGA が未コンフィグの間のプルアップの影響は受けない見込み（データシートでの確認は未）。
- 帯域: 1本あたり最大 20MHz の矩形波。v1 の CVBS（10MHz）の倍だが、Pmod と 33Ω の組み合わせで問題ない速度。

## 3. 受信状態（ゲイン）の送り方

FPGA の復調は位相だけを使うので、**ゲインが無くても映像は出る**。ゲインなどは次の用途に使う。

- 「キャリアなし」の判定（ダイバーシティで、受信していない側を確実に外す）
- 将来の画面表示（ゲイン、信号強度、AFC のずれ）と、ゲインからの受信電力の推定

### 物理層

- XIAO の D10 から UART1 TX、**2Mbaud 8N1**。
- Dock の **USB-A 端子**は D+ / D− が FPGA のピン（L6 / K6）に直結している（Sipeed の nestang-25k が USB ゲームパッド用に同じピンを使っている）。USB ケーブルの A オス側を切って、緑（D+）を XIAO-A の D10、白（D−）を XIAO-B の D10、黒（GND）を GND につなぐ。
- 赤（VBUS 5V）は XIAO の給電に使える可能性がある。**Dock の USB-A に 5V が常時出ているかは未確認**なので、テスターで測ってから使う。出ていなければ、今どおり Dock 裏の 5V パッドから J2 へ線を引く。

### パケット（8 バイト、ゲインを書いた直後と、少なくとも 2ms ごと）

| バイト | 内容 |
|---|---|
| 0 | 0xC5（同期） |
| 1 | 連番 |
| 2 | ゲイン（ベンダーのゲイン表のインデックス） |
| 3 | フラグ: [1:0] IQ レーン（C5VRX-5 は 2 = ultrafine 固定）、[2] キャリアあり、[3] AFC ロック、[4] 200ms 以内に映像を検出、[5] PAL |
| 4 | チャンネル番号 0〜47（R1〜R8, A, B, E, F, L） |
| 5 | AFC の周波数オフセット（符号付き、25kHz 単位） |
| 6 | 信号強度 0〜100（C5VRX のメニューのバーと同じ値） |
| 7 | チェックサム（0〜7 の合計が 0） |

ゲイン変更から FPGA に届くまでの遅れは 50µs 程度（1 ライン未満）。

## 4. FPGA 側の処理（`fpga_iq/`）

```
IQ 8本 ─ iq_os_rx ─ fm_demod ─────────────── cvbs_decode_fm ─ chan_buf ─ SDRAM ─ display ─ HDMI
        150MHz で   位相LUT→差分→[1 3 3 1]   レベル自動調整(off/scale)
        取り込み     →20MS/s, クリック数       同期分離・輝度・640画素（v1 と同じ）
USB-A ─ link_rx（UART パケット）──→ 「キャリアなし」を品質へ
```

| ブロック | 内容 |
|---|---|
| `iq_os_rx` | 150MHz（3.75 倍）で 8 本を取り込み、変化点から 40MHz の位相を追って語の中央で取る。単体試験で ±100ppm、ピン間スキュー 5ns までエラー 0（7ns で 3 語/16 万語） |
| `iq_phase_lut` | 256 通りの IQ → 位相（1024 分割）。セルの中心（2k+1）で計算。原点を囲む 4 セルに印を付ける |
| `fm_demod` | 位相差分（40MS/s）。原点セルを通る差分は半分の重み（C5VRX-5 U85Q と同じ考え）。[1 3 3 1] の低域通過で 2:1 に間引き、20MS/s・4.88kHz/LSB で 75MHz 側へ渡す |
| `cvbs_decode_fm` | v1 の `cvbs_decode` を 8bit に広げたもの。毎ラインの同期先端とバックポーチの周波数から、オフセットと倍率を自動で合わせる（VTX ごとの偏移とキャリアのずれを吸収）。品質に FM クリックの数を加える |
| `link_rx` | UART パケットの受信。20ms 来なければリンク断とみなす |

`cvbs_decode_fm` 以降（`chan_buf`、`sdram_fb`、`display`、`tmds_enc`）は v1 と同じファイル。カラーはまだで、白黒のまま。

## 5. 乗算器・回路規模

| | v1（CVBS 受け） | IQ 版 |
|---|---|---|
| DSP（28 個中） | 4 | **8**（1台あたり: 周波数→輝度の倍率、倍率ループ、輝度、横補間） |
| LUT＋ALU（Yosys、乗算器を LUT にした場合の上限） | 約 4,800 | 約 9,700（23,040 中） |
| FF | 約 1,400 | 約 2,500 |
| BSRAM | 12 | 12（変化なし） |

- FM 復調自体は 4bit×4bit の表引きなので、乗算器を使わない。
- [multiplier_budget.md](multiplier_budget.md) のカラー見積もり（時分割で 16 個）に今回の +4 を足しても 20 個で、28 個に収まる。
- Yosys の数字は GW1N 用の見積もり。Gowin での実際の値は合成で確認する。

## 6. 未確認・注意

1. **MODEM_DIAG のピン出力が本当に 40MS/s の矩形か**: C5VRX の PARLIO RX が 40MHz で読めているので、そう考えている。実機で GAO（Gowin のロジアナ）か FPGA の `iq_lock` で確認する。
2. **Dock の USB-A**: D+ / D− の直列抵抗やプルダウンの有無、VBUS が出ているかは回路図で未確認（この環境から Sipeed のサイトに入れなかった）。UART は 2Mbaud なので、数十 Ω の直列抵抗やプルダウンがあっても動く見込み。
3. C5VRX の内部（PARLIO RX）も同じピンを読み続けているので、配線の容量は小さく保つ（33Ω は XIAO の近く）。
4. C5VRX 側の AFC とゲイン制御はそのまま動く。FPGA 側はそれを前提にしつつ、レベルは自分で合わせ直す。
