# FPGA 乗算器（DSP）の見積もり

2026-10-06（スレッド1）。前提は [interface.md](interface.md)。

## 使える資源（GW5A-25, Gowin DS1103）

| 資源 | 数 |
|---|---|
| DSP（27×18 乗算器、プリアダー付き） | **28** |
| LUT4 / FF | 23,040 / 23,040 |
| BSRAM | 1,008Kbit（56 ブロック） |

入力は 6bit × 20MS/s が2系統、出力は 720p（74.25MHz）。

## 処理ごとの乗算器の数

「単純」は1つの乗算器を毎サンプル1回だけ使う作り方。
「時分割」は DSP を 80MHz で回し、20MS/s の1サンプルの間に4回使う作り方（20MS/s が遅いので可能）。

### 受信1台あたり（20MS/s）

| 処理 | 内容 | 単純 | 時分割 |
|---|---|---|---|
| 同期分離・レベル検出 | 比較と加算だけ | 0 | 0 |
| 輝度・色の分離（色の帯域通過フィルタ） | 9タップ対称 FIR、プリアダーで乗算5回 | 5 | 2 |
| 色の復調 | 色副搬送波の cos/sin を掛ける | 2 | 1 |
| U/V の低域通過 | 移動平均（加算のみ）で 5MS/s に間引き | 0 | 0 |
| バースト位相の追従 | 復調結果を積算するだけ | 0 | 0 |
| 輝度・色の自動レベル調整 | Y に1回、U/V に1回ずつ | 3 | 1 |
| **小計** | | **10** | **4** |

### 出力側（720p、2系統で共用）

| 処理 | 内容 | 単純 | 時分割 |
|---|---|---|---|
| 横方向の拡大 | 約 1040 → 960 または 640 画素、Y/U/V を線形補間 | 3 | 3 |
| 縦方向の拡大 | ダイバーシティは3倍、2画面は2倍の整数倍なので補間なし | 0 | 0 |
| YUV → RGB | 係数4つ | 4 | 4 |
| 明るさ・コントラスト | | 1 | 1 |
| **小計** | | **8** | **8** |

（出力側は 74.25MHz で毎画素動くので時分割できない。）

## 合計

| 構成 | 単純 | 時分割 |
|---|---|---|
| 白黒のみ（色の処理なし。受信1台あたり 1 個） | 1×2 + 2 = **4** | 4 |
| ダイバーシティ（カラー2台分。どちらも常に復調して品質を比べる） | 10×2 + 8 = **28** | 4×2 + 8 = **16** |
| ダイバーシティ（品質の比較は同期だけで行い、色は選んだ1台だけ復調） | 10 + 1 + 8 = **19** | 4 + 1 + 8 = **13** |
| 2画面（カラー2台分） | 10×2 + 8 = **28** | **16** |

## 結論

- 単純な作り方でカラー2台分にすると **28 個ちょうどで余裕がない**。前回「足りなくなるかも」と書いたのはこの場合。
- 20MS/s は FPGA にとって遅いので、DSP を 80MHz で時分割すれば **カラー2台分 + 720p 出力でも 16 個程度**で、28 個の6割弱に収まる。
- **2画面でもカラーにできる見込み**。白黒に落とす必要があるのは時分割を使わない場合だけ。
- 係数が固定の掛け算（フィルタ、YUV→RGB）は、6〜8bit 程度なら LUT のシフトと加算でも作れる。DSP が足りなくなったときの逃げ道になる。LUT は 23,040 個あり、余裕がある。

## 注意

- これは設計前の見積もり。実際の数はスレッド3（FPGA）で合成して確認する。
- C5VRX のサンプルクロック（20MS/s）は色副搬送波に同期していないので、色の復調には NCO（数値制御発振器）と位相追従が要る。NCO の sin/cos は BSRAM のテーブルで作り、乗算器は使わない。
- 色のフィルタのタップ数を増やせば画質は上がるが、DSP はタップ数の約半分ずつ増える。
