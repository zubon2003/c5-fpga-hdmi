# c5-fpga-hdmi

[English README](README.md)

> **実験段階です。至近距離でしか動作を確認していません。** VTX を受信機の
> すぐ近く（机の上、約 1 m）に置いた状態でしか動作を確認していません。
> 受信距離、弱い信号での動作、他の VTX や他のチャンネルは試していません。
> 実用的な FPV 受信機ではなく、動作原理の確認（概念実証）として扱ってください。

[C5VRX](https://github.com/Twotoz/C5VRX) を動かしている ESP32-C5 で受信した
5.8 GHz のアナログ FPV 映像（FM、NTSC）を、Sipeed の **Tang Primer 25K**
FPGA で復調し、HDMI モニターに **1280×720p、59.94 Hz**（CEA の 720p のフレームタイミング）の
カラー映像として表示します（4:3 の映像を左右に黒帯を付けて 960×720 で表示するか、
16:9 に引き伸ばして表示します）。SDRAM のフィールドストアを使うことで、HDMI 出力を
一定のピクセルクロックで出せます。HDZero ゴーグルにはこれが必要です。ゲンロックを
オンにすると、SDRAM を使わずに、約 1 ms の遅延で出力が入力に追従します。

C5VRX-5 のファームウェアは、受信機の生の 4 ビット IQ サンプル
（MODEM_DIAG Q4/I4）を 8 本の GPIO にすでに出しています。FPGA はその
ピンを並列に読むだけです。ゲイン制御、AFC、チャンネル選択は、引き続き
ESP32-C5 が行います。v5.0.464 までの公式リリースは改変なしで使えます。
それより後の版では IQ のピンが 2 本移ったので、[firmware/](firmware/README.md)
に v5.0.523 用のパッチを用意しています（[C5VRX のバージョン](#c5vrx-のバージョン)を参照）。

## 由来

- **[fpvdec / 5G8atv-rf-hackrf-decoder](https://github.com/zubon2003/5G8atv-rf-hackrf-decoder)**
  — このプロジェクトの出発点になった、HackRF One 用のアナログ FPV 映像の
  ソフトウェア受信機（作者のもの）です。fpvdec 自体は、GOROman 氏の
  [famicom-rf-hackrf-decoder](https://github.com/GOROman/famicom-rf-hackrf-decoder)
  をベースにしています。fpvdec の NTSC デコーダと C5VRX 受信系の
  エミュレーション（`--c5`）を、ここでの処理の参考にしました。FPGA の設計は
  新しく書いた HDL です。
- **[C5VRX](https://github.com/Twotoz/C5VRX)**（Twotoz 氏と C5VRX
  コントリビューター）— ESP32-C5 の FPV 受信機です。このプロジェクトは、
  C5VRX の MODEM_DIAG IQ の GPIO 出力（レーンの割り当てとピン順、C5VRX-5 の
  `main/rf.c`）を使い、「C5 を RF フロントエンドにして、信号処理は外部の
  ロジックで行う」という研究（C5VRX-4 の `RESEARCH.md`）に沿っています。
  同期分離には C5VRX-4 の sync flywheel（`SYNC_FLYWHEEL.md`）のライン格子の
  考え方を、FM 復調には C5VRX-5 の U85Q 位相トラッカーと kp ラダーの考え方を
  広げて使っています。[クレジット](#クレジット) を参照してください。

### C5VRX のバージョン

C5VRX-5 の公式リリース **`c5vrx5-v5.0.332`**（commit `24da232`）を、改変せずに
使って確認しました。[C5VRX の Web フラッシャー](https://twotoz.github.io/C5VRX/)
または GitHub のリリースから書き込めます。下の IQ の GPIO の割り当ては、
このバージョンのものです（v5.0.322 も同じでした）。今後のバージョンで変わる
可能性があるので、C5VRX の `main/rf.h` にある `RF_IQ_GPIO_NUMS`（v5.0.482 より
前は `main/rf.c` の `s_iq_pins`）を確認してください。チャンネルは、いつもどおり
C5 側（BOOT ボタンのメニューか USB コンソール）で合わせ、起動時の校正が
終わるのを待ってください。

**公式リリースの `c5vrx5-v5.0.482` 以降は、この結線では動きません。**
C5VRX の PR #263 で、Q 符号が D3/GPIO7 から GPIO2（MTMS）に、I bit 0 が
D10/GPIO10 からユーザー LED の GPIO27（パッドに出ていません）に移りました。
`c5vrx5-v5.0.464` までの公式リリースは元のピンのままです（改変なしで確認したのは
v5.0.332 だけです）。[firmware/](firmware/README.md) の改変版 v5.0.523 は、
両方のビットを元に戻しています。

### 任意: Dock のボタンでバンド / チャンネルを切り替える

Dock のボタンでバンドとチャンネルを切り替え、画面にチャンネルを表示するには、
DAC の下位 2 ピンに UART を足した、改変版の C5VRX-5 が必要です。パッチ
（2026-10-27 に確認した v5.0.523 用と、以前の v5.0.387 用）とビルド手順は
[firmware/](firmware/README.md) にあります。C5VRX の公式リリースでは
ありません。この版では、C5 自身のアナログ映像出力は止まります。それ以外の
機能は、v5.0.464 までの公式のファームウェアで動きます。

## 結線（XIAO ESP32-C5 → Tang Primer 25K Dock J4）

Dock の PMOD J4 のピン番号は、Dock の回路図どおりです。1/2 番が +3V3、
3/4 番が GND、5〜12 番が信号です（左列が偶数ピン、右列が奇数ピン）。
配線する前に、テスターで 1 番ピン（+3.3 V）を確認してください。

```
   XIAO ESP32-C5                         Tang Primer 25K Dock, PMOD J4
   （表面）                                    ┌─────────┐
   GND  ──────────────────────────────── 3/4  │ 2    1  │  +3V3（接続しない）
   D0   (GPIO1)  ── Q bit 0 ───────────── 5   │ 4    3  │  GND
   D1   (GPIO0)  ── Q bit 1 ───────────── 6   │ 6    5  │
   D2   (GPIO25) ── Q bit 2 ───────────── 7   │ 8    7  │
   D3   (GPIO7)  ── Q 符号  ───────────── 8   │ 10   9  │
   D10  (GPIO10) ── I bit 0 ───────────── 9   │ 12  11  │
   （裏面の JTAG パッド）                      └─────────┘
   MTDO (GPIO5)  ── I bit 1 ───────────── 10
   MTDI (GPIO3)  ── I bit 2 ───────────── 11
   MTCK (GPIO4)  ── I 符号  ───────────── 12
   MTMS (GPIO2)  ── 接続しない（公式の C5VRX-5 ファームウェアが駆動）
```

| J4 ピン | FPGA のピン | `iq[n]` | 信号 | XIAO のピン | ESP32-C5 の GPIO |
|---|---|---|---|---|---|
| 1, 2 | +3V3 | – | 接続しない | – | – |
| 3 か 4 | GND | – | グラウンド | GND | – |
| 5 | C11 | 0 | Q bit 0 | D0 | 1 |
| 6 | C10 | 1 | Q bit 1 | D1 | 0 |
| 7 | B11 | 2 | Q bit 2 | D2 | 25 |
| 8 | B10 | 3 | Q 符号 | D3 | 7 |
| 9 | D11 | 4 | I bit 0 | D10 | 10 |
| 10 | D10 | 5 | I bit 1 | MTDO（裏面パッド） | 5 |
| 11 | G11 | 6 | I bit 2 | MTDI（裏面パッド） | 3 |
| 12 | G10 | 7 | I 符号 | MTCK（裏面パッド） | 4 |

- 2 つの 3.3 V 電源同士はつながないでください。どちらのボードも、それぞれの
  USB から給電します。GND は必ず共通にしてください。
- 配線は短く（目安 10 cm 以下）してください。IQ のビットは 80 MHz で変化します。
- XIAO の裏面の JTAG パッドにある I の 3 本は、はんだ付けが必要です。
- PMOD DVI は **J5**（真ん中の PMOD）に挿します（2026-11-01 までは J6）。

SDRAM モジュールは Dock の 40 ピンヘッダー J3 に挿します（ピン配置は Sipeed の
TangPrimer-25K-example の `nestang-25k` と同じ）。ゲンロックオフ（起動時の設定、
HDZero ゴーグルに必要）では、映像はすべて SDRAM を通ります。ゲンロックをオンにする
（`g`）と SDRAM を迂回するので、モジュールなしでも使えます（`g` を押すと映ります）。

任意の受信機リンク（改変版の C5 ファームウェアのときだけ）。Dock の USB-A
ホスト端子 **J13** を使います（USB-A オスの変換基板などで線を出します）。
J13 の D+ / D- は 0 Ω を通って FPGA の L6 / K6 につながり、両方に 15 kΩ の
GND へのプルダウンがあります。USB の通信ではなく、この 2 本で 115200 bps の
UART を流しています。

| USB-A ピン | FPGA のピン | 信号 | XIAO のピン | ESP32-C5 の GPIO |
|---|---|---|---|---|
| 2（D−） | K6 | C5 の TX → FPGA の RX | D4 | 23 |
| 3（D+） | L6 | FPGA の TX → C5 の RX | D5 | 24 |
| 4（GND） | – | グラウンド | GND | – |
| 1（VBUS） | – | Dock の +5 V | つながない | – |

XIAO を自分の USB から給電しているときは、VBUS をつながないでください（XIAO の
5V ピンはその USB の VBUS と直結しています）。XIAO に抵抗 DAC をつけていた場合は、
D4/D5 の抵抗を外してください。2026-11-01 にチャンネル報告（`E1 5705`）が
届くことを確認しました。最初のビルドは D+ / D- が逆で、何も届きませんでした。

## 書き込み

ビルド済みのビットストリームを [GitHub のリリース](../../releases) に添付して
あります（Gowin Programmer 用の `c5_fpga_hdmi.fs`、ほかの書き込みツール用の
`c5_fpga_hdmi.bin`）。v0.2.0 までのリリースは以前の構成です（SDRAM なし、
PMOD DVI は J6、受信機リンクは J5）。

Gowin Programmer（Education 版、ライセンス不要）で書き込みます。デバイスは
**GW5A-25A / GW5A-LV25MG121NC1/I0** です。

```powershell
# SRAM（電源を切ると消える）
programmer_cli.exe --device GW5A-25A --run 2  --fsFile c5_fpga_hdmi.fs
# 外部フラッシュ（電源投入時に起動、約 3 分）
programmer_cli.exe --device GW5A-25A --run 54 --fsFile c5_fpga_hdmi.fs
```

Programmer がデバイス ID の不一致を出した場合は、ボードが GW5A-25B の
可能性があります。`scripts/build.tcl` の `set_device` を変えて、ビルドし直して
ください。

## 使い方

XIAO（C5VRX-5 を VTX のチャンネルに合わせたもの）と Dock に電源を入れ、
HDMI をつなぎます。HDMI 出力は常に 1280×720、59.94 Hz（59.945 Hz）です。VTX がついていれば
1 秒ほどで映像が出ます。VTX がないときは、映像部分にノイズが表示されます。画面
右上の小さな四角は、水平同期を検出できている間は緑、できていないときは赤に
なります。

遅延: ゲンロックがオフのとき（起動時）、HDMI 出力は独自のクロックで動き、
SDRAM のフィールドストアからフィールドを表示します。加わる遅延は約 0.5 ms 〜
1 フィールド（16.7 ms）、平均約 8 ms です。出力と入力のクロックの差で遅延は
ゆっくり変わり、数分ごとに 1 フィールド分戻ります（そのとき 1 フィールドが
飛ぶか 2 回表示されます）。ゲンロックのモード（`g`）は出力を入力に同期させ、
SDRAM を迂回します。表示は 24 ラインのリングから直接読むので、入力からの遅れは
画面の上で約 0.2 ms、下で約 1 ms です（計算値で、実測ではありません）。HDZero
ゴーグルは、ゲンロックによるタイミングの変化についていけません。

受信機リンクがあるときは、Dock の H11 のボタンでバンドが、H10 のボタンで
チャンネルが切り替わります（R, A, B, E, F, L、1〜8）。新しいチャンネル名
（`F3` など）が画面の右上に 3 秒間表示されます。起動時にも 1 回表示されます。

Dock の USB デバッガには UART（2 つ目の COM ポート、1 Mbaud）があります。
1 文字送ると、実行中に設定を変えられます。`P` / `W` 以外の設定は、最後に変えてから
2 秒後に設定用フラッシュに保存され、次の起動時に戻ります（`src/cfg_flash.v`、最後の
4 KB セクター 0x7FF000。`R` の応答の最後のバイトが保存の状態）。ビットストリームを
書き直しても残ります。下の「起動時」は、保存した設定が無いときの値です。

| キー | 動作 |
|---|---|
| `P` / `W` | 画像（起動時。保存しない）/ 復調した 1 ラインの波形モニター |
| `u` / `d` | 有効ラインの開始を −/+ 1 |
| `h` / `l` | 画像の開始位置を −/+ 0.2 µs |
| `f` | フィールドの上下補正の向き（インターレース） |
| `c` | 色のオン・オフ |
| `v` | V の符号（色相） |
| `a` / `z` | 色の濃さ +/− 0.25 倍 |
| `[` / `]` | 色相 −/+ 11.25° |
| `m` | FM 復調の方式: 0 隣接差分、1 PLL 速い、2 PLL、3 PLL 遅い（起動時） |
| `A` | 映像を 4:3（左右に黒帯、960×720。起動時）/ 16:9 に引き伸ばし |
| `g` | 出力のゲンロックを順に切り替え: オフ（起動時。74.18 MHz 固定、SDRAM フィールドストア）→ フロントポーチのライン → ピクセルクロック（PLL の位相シフト）→ オフ。ゲンロックの 2 つのモードは SDRAM を迂回（低遅延、モジュール不要） |
| `K` | SDRAM の読み出しタイミングのテスト（結果は `T` のワード 13） |
| `k` | SDRAM のクロックを反転してからテスト |
| `T` | 内部状態（同期、レベル、色のロック、受信機のチャンネル、SDRAM の状態、ピクセルクロックの計測値） |
| `R` | 上の設定を読み出す（`IQLR` と 8 バイト。並びは `src/top.v` の `settings`） |
| `C` `S` `B` `G` | ロジアナの取り込み（生の IQ、シンボル、FM 検波出力、色信号） |

`scripts/viewer.py` は PC 用のテストアプリです。UVC キャプチャ装置経由で
HDMI の出力を表示し、UART で FPGA を操作します。

- **映像**: ウィンドウの大きさに合わせて拡大縮小します。F11（または View >
  Fullscreen）で全画面、Esc で戻ります。
- **操作パネル**: 上の設定をすべてボタンで操作できます（表示モード、4:3 / 16:9、
  ゲンロックのモード、FM 復調、色、色相、色の濃さ、画像の位置、SDRAM のテスト、
  スナップショット、録画、ロジアナの取り込み）。パネルには FPGA 自身の設定を
  表示します。UART を開いたとき、キーを送るたび、1 秒ごとに `R` で読み出します
  （`R` のない古いビットストリームでは、送った内容から推定します）。
- **ライブステータス**: `T` を 1 秒ごとに読んで表示します（同期、フィールド、
  レベル、色のロック、受信機のチャンネル、ピクセルクロック、SDRAM のテスト結果）。
- **Device** メニュー: キャプチャ装置を選びます（初期値は "C8 USB3.0 Video"、
  なければ最初の映像デバイス。`--device`、`--list-devices`）。
- **Port** メニュー: UART を選びます（Auto は Dock のデバッガの 2 つ目の COM
  ポートを FTDI のシリアル番号で探します。`--port`）。
- ボードやキャプチャ装置を抜いて挿し直すと、キャプチャと UART は自動で
  つなぎ直します。
- キーボード: 上のキーに加えて、`s` スナップショット、`r` 録画、`q` 終了。

リポジトリ直下の `viewer.bat` をダブルクリックすると起動します（先に必要な
ものを確認し、引数はそのまま渡します）。コマンドで起動する場合:

```powershell
py -3 scripts\viewer.py
py -3 scripts\viewer.py --device "C8 USB3.0 Video" --port COM4
```

必要なもの: numpy、pyserial、Pillow を入れた Python 3、PATH の通った ffmpeg。
`scripts/iqla.py`、`demod.py`、`fm_model.py`、`resampler_model.py` は、各段を
実機で検証するのに使った PC 側のツールとビット単位のモデルです。

## 仕組み

```
XIAO ESP32-C5（C5VRX-5。公式版、またはリンク用の改変版）: RF、ADC、ゲイン、AFC
  │ MODEM_DIAG Q4/I4 を 8 本の GPIO に出力、約 80 MHz、クロックなし
  ▼
Tang Primer 25K
  IDES8 入力         675 MS/s、IQ シンボルあたり 8.4 サンプル
  iq_resampler       位相追従リサンプラ（バイト単位の Alexander 型位相比較）
                     → シンボルあたり 1 バイトの IQ、約 80 MS/s
                     （C5 と Dock の水晶の差、約 30 ppm を追従）
  fm_demod           振幅で絞る PLL（または隣接差分）、22 タップの移動和
  video_in           同期分離（ヒステリシス、パルス幅、フライホイール）、
                     フィールドとパリティ、バックポーチと同期の深さから
                     黒と白のレベル、1 ライン 640 点を 8 ラインのリングへ
  sdram_fb           SDRAM モジュールのフィールドストア（4 フィールド分）。
                     入力リング → SDRAM → 8 ラインの出力リング。出力は
                     入力に合わせなくてよい（ゲンロックオフ）。ゲンロック
                     オンでは、video_in が出力リングに 24 ラインのリング
                     として直接書く（SDRAM の迂回）
  chroma             バーストに周波数ロックした 3.58 MHz の NCO、
                     ライン間で平均したバースト基準（色相と ACC）、
                     1.6 µs の色のローパス、上下 2 ラインの色の平均
  display            縦方向の補間で 240 → 720 ライン（フィールド 2 は
                     1.5 行下に配置）、BT.601 で RGB へ
  video_timing       CEA の 1280×720p のタイミング: 1650 × 750、74.1818 MHz
                     （59.945 Hz、PLL を 2 段直列）。初期値は自走。任意のゲンロックは、
                     2 つ目の PLL の位相を動かしてピクセルクロックを合わせる
                     （PI 制御）か、ポーチのラインの長さを変える
  TMDS / OSER10      → PMOD DVI（J5）
```

立ち上げで分かったこと:

- C5 の GPIO の IQ は 80 MHz で更新されています（C5VRX 自身は 40 MS/s で
  取り込んでいます）。
- フレームの長さが毎フレーム変わる出力（以前の版は、入力を待つために最後の
  ラインを繰り返していました）は、キャプチャ装置では映りましたが、HDMI
  モニターでは映りませんでした。また、映像部分のラインの長さを変えると、
  キャプチャ装置で画像が斜めにずれました。垂直フロントポーチのラインだけ
  長さを変える方式はモニターとキャプチャ装置では映りましたが、HDZero
  ゴーグル（HDMI 入力）は変化のたびに同期し直して真っ白になりました
  （フレーム単位で全ラインを ±1 ピクセル変える方式でもちらつきました）。
  ピクセルクロックのほうを動かす方式（PLL を 1/8 VCO 周期ずつ位相シフト、
  今は 112.3 ps。出力の分周比は整数である必要があり、以前の小数分周 3.625 では
  位相が 3 VCO 周期で一周して周波数が変わりませんでした）でも、ゴーグルは
  白くなりました。そこで今は、出力を一定のクロックで動かし、入力との差を
  SDRAM のフィールドストアで吸収しています（起動時はゲンロックオフ）。
- HDZero ゴーグルはファームウェア 9.6.0-rc1 以降、標準でない 1631 × 750、
  73.33 MHz（以前のタイミング）では真っ黒になります。そのため標準の
  1650 × 750 のフレームにしました（74.1818 MHz。CEA の 74.1758 MHz より 81 ppm 高い）。
  PLL の小数逓倍では映像が出なかったので、整数逓倍の PLL を 2 段直列にしています
  （`src/pll.v`）。
- くっきりした横の輪郭（OSD の文字）は、フィールドの切り替わりで今も約 1
  ラインずれます。各フィールドを 1 枚ずつ表示している（ボブ方式）ためです。
  フィールドストアには前のフィールドも残っていますが、2 つのフィールドを
  組み合わせる表示（ウィーブ）はまだ実装していません。
- 開発で使ったキャプチャ装置は、書き込み直後に真っ黒のままになることが
  ありました。表示モードを一度切り替える（`W` → `P`）と戻ります。

使用資源: LUT 約 5,000（ALU を含む論理セル約 7,900）、BSRAM 56 個中 41 個、
DSP ブロックの 72 %、PLL 6 個中 2 個。

詳しい開発記録（日本語）は [docs/DEVLOG.ja.md](docs/DEVLOG.ja.md) にあります。
